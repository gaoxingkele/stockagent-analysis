# S20 长周期算法研究与 Harness 执行计划

日期：2026-09-13。状态：规划完成，训练与新运行器尚未执行。研究代号 `S20-Safe / v4`。

本文是可供后续执行器逐阶段执行的工作规范，不是新算法已通过验证的声明。机器可读任务图见 `config/s20_v4_harness_plan.json`。采用 SmartGoal 四专家提案、交叉质疑、工程收敛流程；研究方法、交易、统计由独立专家讨论，主执行者承担工程整合。

## 1. 决策摘要与长期目标

用户希望TopN里的股票大多能赚钱，小涨、大涨均可；上涨和下跌概率同时很高的股票应受到惩罚。把这一意图转成可检验目标：

1. 在明确的持有/退出规则下，提高扣费后的盈利率和安全盈利率。
2. 降低相对入场价跌破-5%/-8%/-10%的频率，同时控制组合尾部损失。
3. N是每日正式推荐的上限，允许不足或0只；完整报告减少推荐带来的覆盖损失。
4. 输出上涨、下跌、联合路径概率以及独立的效用排名，不能把排名分数当成概率。
5. 以同标签、同事前股票集合、同覆盖和同执行条件下的旧版为参照，不以换目标制造进步。

不设置“模型保证任何一只都不跌”的承诺。近100%只能是待检验的高选择性目标，必须同时有足够样本、风险置信界和覆盖率，不能由几个成功案例宣布达成。

优先方案是：保留旧S20-20R的上涨信息，增加风险辨别和可拒绝推荐的选择层；联合四分类、条件风险与尾部分布作为竞争路线。序列网络、图模型和路径生成保留在长计划中，按证据逐级启动。

## 2. 当前证据和不能忽略的负结果

来源：`CHECKPOINT_S20_20260912.md`、`config/s20_v3_results.json`、`docs/research/s20_v3_opportunity_risk_20260912.md`。

| 已知结果 | 对新计划的约束 |
|---|---|
| 旧S20-20R按v3新标签的复盘Top20即时有效35.44%，先行下跌55.83% | 有上涨排序信号，但不是低风险可执行策略 |
| v3平衡版32.10%/59.33%，24低相关特征也未改善 | 不把重新训练、去相关或调风险权重直接视作升级 |
| v3预测上涨67.22%而实际32.10%，预测下跌19.44%而实际59.33% | 首先审计概率及分布漂移，不能直接用预测90%作推荐门槛 |
| 325万股票日期标签，但同股/同日/20日窗口高度相关 | 条数不是独立统计证据量 |
| 2026-01-27～08-05已查看并影响标签设计 | 永久列入已知开发资料，不重新包装成封存验证 |
| 旧N3有9条原因覆盖错误，新标签已独立纠正 | 将这9条作为永久回归样例；旧基线必须带标签版本 |

本次额外源码检查确认以下实现方式，但尚未量化它们造成的绩效影响：

- `src/stockagent_analysis/s20_v3.py`以连续股票记录取D+1与20日窗口；停牌股票不等于20个市场交易日。
- v3用原始OHLC与当前ST/行业元数据；除权误标及幸存者偏差的实际规模需要审计，不能凭风险存在就断言全部结果错误。
- 旧对照排除了依据未来路径确定的歧义样本；这可用于条件标签研究，但不能构成事前可执行选股集合。
- `research/backtest/paper_trade_harness.py`允许`overwrite=True`；`complete_20d`使用`>=20*0.8`；执行实例用固定`limit_pct=9.8`。
- `research/backtest/engine.py`用交易日最终`pct_chg`判断开盘是否可成交；这是新开盘执行器必须消除的未来信息依赖。
- `scripts/train_s20_v3.py`只按开发缓存是否存在决定重用；新harness需要数据、代码、标签、环境指纹驱动缓存失效。

以上旧模块保持不变。新执行器通过适配和测试复用有用部分，不继承这些不满足新契约的默认行为；也不把旧代码里的Sharpe锚移植成S20基线。

## 3. 专家立场、分歧与解决实验

| 视角 | 独立提案 | 对其他方向的质疑 | 收敛决策 |
|---|---|---|---|
| A：时序/损失 | 旧锚风险修正、联合/条件概率、尾部分布；小模型先行 | 直接上Transformer或把边际概率相乘，不能解决联合路径 | 首轮主攻E02/E03/E04，复杂方法须有误差证据 |
| B：量化/交易 | 日历、复权、时点、成交与现金账本先行 | 触达不等于卖出；同日止盈、跌停止损、事后延迟入场会虚增成功 | 数据和执行器成为训练前硬依赖 |
| C：统计 | 选择后校准、延迟反馈、区块验证、试验登记 | 共形边际覆盖不等于TopN条件风险；小样本零跌不等于安全 | 分层证据门，相关样本不足时明确`insufficient_evidence` |
| D：工程整合 | 轻量harness、统一契约、不可变产物、失败归因 | 平台开发和无界试验会吞掉研究预算；脏工作树不可隐式丢失 | 先建最小运行闭环，算法分阶段竞争，冻结一个冠军再前瞻验证 |

保留的分歧及解法：

| 分歧 | 解法 |
|---|---|
| 终值盈利是否替代旧触达目标 | 不替代。旧机会轨、期限安全盈利研究轨、实际交易轨分别报告 |
| 惩罚风险应多重 | 只在内层开发选择有限权重；同时设独立风险门槛，输出完整收益风险前沿 |
| 低波动是否足够 | 必须胜过ATR/市场状态/流动性基线；按这些因素分层后的条件增量才算新信息 |
| 70%、80%、90%哪个盈利目标合理 | 一期按相对基线改善验收；80%/5%与90%/1%列挑战档，不承诺可达 |
| 共形校准是否可作为安全保证 | 只作有假设约束的候选方法；选择后的损失非单调、时间依赖和反馈延迟须独立验证 |
| 是否直接运行mylib的paper_harness | 当前是论文流程，不能直接充当股票实验运行器；只借鉴其持久化/哈希/候选隔离模式 |

## 5. 数据与标签契约：三条轨道

### 5.1 O轨：`opportunity_v3_compat`

逐字保留v3标签含义及版本，用于复现旧结果。另做`opportunity_calendar_pit_v4`修正轨，使用市场日历和可审计经济价格，给出旧新标签转移矩阵。修正了标签后，旧模型也必须重评，不能拿35.44%直接作新任务基线。

### 5.2 P轨：`safe_profit_20d_research`

这是新研究任务假设，不静默取代用户此前认可的触达目标。

- 信号D：按固定预测时刻之前可得的特征评分。以市场交易日历定义D+1和D+20。
- 主上涨事件U：D+1开盘基准进入、D+20收盘基准退出，扣除预先固定费用后收益>0。
- 主风险事件B5：整个D+1～D+20窗口的经济持有价值，相对入场经济成本曾低于-5%。
- 次级风险B3/B8/B10及终值+3/+5/+10/+15/+20只作预注册分层/敏感性，不在测试期挑最漂亮标签。
- 主四类：A=U且非B5，B=U且B5，C=非U且非B5，D=非U且B5。
- 同时报MAE（相对入场价）与峰谷最大回撤，二者名称和分母严格分开。
- 价格触达后继续持有的回落不能从P轨风险中消失。

使用单位名义持仓的固定成本假设生成研究标签；真实数量导致的最低佣金、整手、资金占用在T轨处理。原始价格用于成交，公司行动账本用于经济收益和持仓调整；不能用未来可得的复权因子制造当时特征。

D+1无有效开盘/不可成交时标记`unfilled_or_unknown`，预测记录仍保留，不自动延期买入，也不把它填成A/B/C/D。D+20无法退出时保留窗口诊断和`exit_pending`，实际持仓与风险延续到可退出日；交易结果的`label_available_at`相应延迟。缺失、退市、未知估值不能静默删除，必须报告结果上下界与未解决占比。

### 5.3 T轨：实际交易与组合

主退出策略先固定为期限退出。提前止盈/止损、追踪止盈、延迟入场是独立实验，不能随模型调优一起改。

- D收盘后的决策只能在下一合法成交时点执行；当日买入不可假设当天卖出。
- 市场、板块、特殊状态、规则生效日期驱动交易规则，不能统一用9.8%常量。
- 不用当日最终涨跌幅判断开盘是否可买。开盘价、涨跌停价、当时可用状态和成交数据分别记录；无队列信息时给保守成交情景。
- 跳空越过止损、跌停无法卖出不得按止损线理想成交。
- 同日高低价顺序不明的股票保留在事前候选中；对路径事件报告界限，对交易用保守顺序；有分钟数据时记录覆盖，不只补成功样本。
- 输出推荐、订单、成交、建仓回合、组合净值五层账本。持仓中再次推荐默认只记信号、不再开仓；加仓、冷却是可选消融。
- 明确现金、最大持仓、资金占用、交易单位、费用和流动性参与率；禁止每日Top20都假设有一份新资金。
- 沪深与北交所按独立市场配置和分层结果处理；第一轮优先审计现有沪深数据，北交所作为后续独立验证，不混用规则。
- 不重新引入用户已取消的“行业最多4只”限制。行业/市场集中度先做暴露和压力报告；任何新集中度约束属于独立策略变更。

### 5.4 时点与数据冻结字段

每行至少包括：`signal_date, prediction_at, feature_available_at, exchange, board, ts_code, listed_at, status_asof, entry_planned_at, horizon_end_at, label_available_at, corporate_action_version, missing_reason`。

每次数据集保存源文件哈希、行数、日期/市场覆盖、schema、处理代码哈希、标签契约哈希、退市/ST/复权可用性。历史计划中声称已有的数据必须核验真实文件与时点；未核验不记作具备。

不在首轮做：大规模强化学习、端到端利润最大化黑箱、合成牛市样本扩充、同时搜索几十个止盈止损参数、用LLM直接给股票概率。它们若以后进入，也必须证明解决了已定位的残余问题。

首轮假设优先级：E02 → E03/E04 → E08/E09 → E06/E10。E11～E17不是必须完成的清单；只有基本数据与基线成立，且有可证伪的缺失信息假设时才消耗预算。

## 7. 排名、风险惩罚和拒绝机制

对P轨四类定义：`pA+pB+pC+pD=1`，`p_up=pA+pB`，`p_down5=pB+pD`，`p_safe_profit=pA`。

候选效用：

`utility = pA - lambda*pB - mu*pD - nu*pC`，有限候选约束 `mu > lambda > nu >= 0`。

简单比较器保留`p_up - beta*p_down5`和直接`pA`排序。只在训练/决策开发段选一小组权重，测试期冻结；强惩罚训练可能改变概率含义，因此排序损失和概率校准分别验收。

条件分解路线可以用`P(U)*P(B5|U)`计算危险上涨联合概率；不能用`P(U)*P(B5)`假装二者独立。

独立选择层要求同时满足：足够上涨证据、风险低于候选门槛、数据可用、校准状态正常、模型分歧可接受。一个极高上涨分不能抵消触发的风险硬门槛。门槛是研究参数，未经选择后校准验证不叫90%置信推荐。

正式输出每日最多N只，N候选只限1/3/5/10/20。保留未入选理由：`risk_high, upside_low, uncertainty_high, data_stale, calibration_unreliable, already_held, capacity, unfilled`。无样本时盈利率/风险率为null、覆盖为0，不能报0风险100%成功。

## 8. 特征集：以条件增量替代“低相关即正交”

预注册六组：价格位置/收益路径、波动/尾部/跳空、流动性/量价、市场/行业环境、可审计基本面/估值、事件/状态。先使用已可重建数据，新增数据必须记录其实际发布日期。

训练段内做相关聚类或代表筛选；外层测试只评价，不重新挑特征。每组至少检查：

1. 删除整组后安全盈利/下跌预测是否变差；重要性不只来自模型训练gain。
2. 控制ATR、流动性、市场状态后是否有条件增量。
3. 同日股票差异与日期环境差异分开；市场变量不能被宣传成同日独立择股信号。
4. 多折、多种子、不同波动/市场状态下方向和贡献是否稳定。
5. 随机特征、时间打乱、随机图/近邻等负对照是否产生假优势。

最终因子卡标记`stable / regime_dependent / redundant / unverified`。不承诺正交；如使用PCA/正交残差，也只在训练段拟合，并验证统计正交是否真的改善样本外决策。

## 9. 验证、延迟反馈与封存规则

### 9.1 开发期的五段时间结构

每外层折顺序为：fit → tune → calibration → selection-policy → outer-test。小样本情况下可用严格时序交叉拟合生成中间预测，但不能共享未来标签。

所有边界按`label_available_at < next_segment_prediction_at`清除跨期样本；固定20行purge仅作为最小保护，不替代停牌/数据迟到后的真实成熟时刻。特征筛选、锚评分、超参、校准、选择门槛均必须在各自允许的段内完成。

旧模型对训练行提供的锚要是OOF/更早模型预测，不能把拟合过自己的训练得分交给风险模型。样本抽样仅用于训练预算；外层评价尽量用同一个完整事前股票集合。资源不够时冻结统一子集，禁止不同模型使用不同竞争集合。

### 9.2 延迟校准

先比较扩展、滚动、时间衰减与不校准对照。每天的校准状态只读已成熟标签；初期统一在20日到期后加入样本，避免“早到的下跌标签立即加入、成功标签还在等”的反馈偏差。提前风险事件更新只允许单独的延迟/生存模型实验。

全市场及入选子集分别报告Brier、logloss、可靠性图、尾部和门槛附近误差。成熟历史频率是可部署常数基线；按测试总体真实频率构造的常数仅标作事后诊断参考，不能伪装预测方法。

漂移分两类：无标签的特征/预测/结构漂移可以触发保守降覆盖；有标签的绩效漂移只能根据成熟队列判断。不得将无标签警报称为已观测到亏损改善或恶化。

### 9.3 风险—覆盖和统计证据

主图是安全盈利率、-5/-8/-10风险、推荐覆盖的前沿；同时报告固定TopN与可拒绝策略。比较至少包括全日历结果、相同活跃日期结果、相近覆盖率结果，匹配规则预先固定，不能利用结果挑“共同好日子”。

保存信号数、唯一股票数、交易日数、连续推荐episode数、非重叠期限组数。主区间用按日期成对区块重采样，整块保留横截面相关性；块长20/40/60作预注册敏感性，同时给股票episode聚类敏感性。

罕见大跌或零失败时，普通bootstrap可能给出虚假的零宽区间，禁止用它宣称风险上界为0；缺少适用的保守估计与足够块数时，门禁返回`insufficient_evidence`。独立同分布且0失败的示例上界为`1-0.05^(1/n)`，100个独立观察仍约2.95%；股票重复推荐不满足这一独立样本假设，该公式仅作解释示例，不作为本项目默认门禁。

### 9.4 分层验收，数值是预注册研究目标

| 层级 | 门槛 | 未通过怎么办 |
|---|---|---|
| G0 正确性 | 时点、账户守恒、日历、标签、不可成交、缓存指纹、复现检查全过 | 停止下游训练/绩效声明，定位并重建受影响产物 |
| G1 开发筛选 | 相近覆盖下处于收益风险非支配前沿，且不靠不可成交/未来筛选获胜 | 淘汰或保留负结果；不必要求每月都胜出 |
| G2 候选收敛 | 同覆盖的安全盈利改善与严重风险改善有一致方向，多折/种子和压力结果不过度集中单一行情 | 若只是风险/收益交换，标tradeoff，不称双重改善 |
| G3 相对升级证据 | 新前瞻样本中，安全盈利差的成对95%区间下界>0，-10%风险差的上界<0；不足时不自动改用宽松标准 | 不晋级；允许只形成有价值的研究结论 |
| G4 高准确挑战档 | 盈利率单侧95%下界>=80%，-10%风险单侧95%上界<=5%，至少30%信号日有推荐 | 未达到即未达到，不在同一封存期事后下调目标 |
| G5 远期挑战档 | 盈利率下界>=90%，-10%风险上界<=1%，保持同一覆盖底线 | 可不可达由数据决定，不是阶段交付承诺 |

G3与G4是不同主张：可能胜过基线但离高准确目标很远；也可能某种行情里高准确但没有相对优势。至少60个成熟信号日只是初次评估入口，还需预先功效分析支持足够日期块/episode；不能因满足60天自动通过。最终只保留一个冠军与固定基线检验，开发中的全部模型/权重/阈值/N/退出规则都计入试验账本。

正式确认以G3为主主张，预先固定G3→G4→G5的层级检验顺序，不能三个门任意一个通过就宣布总体成功。每一门要求其中全部条件共同成立；前级未通过时，后级结果只作描述，或另开新封存协议验证该独立主张。

### 9.5 真正未知的验证窗口

封存起点是**模型、校准更新算法、风险阈值、退出规则最终冻结之后**的第一个合格预测时点。不是固定选2026-08-06，也不是把已查看的08月样本重新叫测试。

验证期允许按事前冻结的算法用已成熟历史更新校准，但不能人工改参数；记录每次状态。静态冠军的模型权重保持冻结；若冠军本身是在线学习方法，须在封存manifest里事先固定更新算法、窗口、学习率、频率及资源界限，每次更新保存模型快照。研究者只看运维状态、不看封存绩效，直到预注册评估时点。风险紧急事件可以中止，但不能中止后换规则还沿用同一独立验证名称。读取、解封、再使用全部登记。

若要60个新信号日全部完成20日观察，从第一条冻结预测起通常需约80个市场交易日，停牌/数据迟到可能更久。再训练不能压缩这个等待时间。

### 10.3 状态、恢复与越界保护

运行状态：`PLANNED → READY → RUNNING → VERIFYING → COMPLETED`，失败分为`FAILED_INFRA`、`FAILED_VALIDITY`。科学决策独立为`PROMISING / TRADEOFF / NO_GAIN / INSUFFICIENT_EVIDENCE / REJECTED`，训练正常结束不等于科学成功。等待标签是`WAITING_MATURITY`，不是程序故障。

- 阶段依赖及数据哈希匹配后才READY；每次参数、标签或筛选规则改变产生新trial。
- 基础设施失败可在同配置下新建attempt，最多2次；科学失败不得当重试静默改参。
- 原子发布产物清单；RUNNING需要心跳及受控进程信息，重启后先核验，不重复启动同一模型。
- 中间checkpoint必须绑定全部输入哈希，只有一致才恢复。存在同名缓存不等于可重用。
- 并发上限首轮1个训练作业；测量内存后可到2个。使用明确CPU线程、GPU分配、单任务超时和总预算。
- 到预算上限输出已完成结果与未完成状态；禁止为了“成功”无限搜索。
- 原始预测、订单和成熟结果附加写；更正追加revision链，不原位改历史推荐。
- 当前工作树有未提交S20-v3文件及用户pool_e修改。首步保存来源清单和补丁/文件哈希；不得stash、reset或替用户提交无关内容。仅以审计过的研究源快照建立候选环境。
- 自动允许的写路径限新研究模块、其测试/配置/报告和独立output目录；生产模型、池子、网页、21:00任务和外部下单默认禁止。
- 封存评估由受限评估组件读取；人工研究与调参组件拿不到封存标签。仅manifest允许的冻结在线更新器可以按`label_available_at`消费已经成熟的记录，且只能执行预注册更新并记录状态；这不开放人工查看绩效或自由重训权限。单纯在README里写“别看”不算访问隔离。

### 10.4 故障归因与改进记录

每次失败记录`where × why`：

- where：data / labels / split / model / calibration / selection / execution / portfolio / runtime。
- why：availability_leak / stale_cache / target_mismatch / dual_high / safe_but_flat / drift / dependence / optimistic_fill / oversearch / insufficient_sample。
- 每个改进提案声明拟修复的错误、保持不变的条件、预期可观察结果、对应消融。
- 仅程序产出的同条件比较可以记作改进证据；专家文字判断只能生成假设。

## 12. 预算、节奏与停止规则

以下是建议研究预算，H00资源probe后绑定，不是本次已启动的任务：

- 首轮12个模型配置槽，含复现/简单/锚/联合/条件基线，最多2个种子×3外层折=72个模型级fit预算；多头模型必须额外记录底层booster数量和真实CPU/GPU消耗。
- 最多3个入围候选补齐第3个种子与稳定性分析；不能用挑种子替代报告分布。
- 模型之外，校准方案每候选最多3种、选择/惩罚政策每候选最多6种；均登记为独立可选择pipeline，不能藏在“只是后处理”里无限搜索。
- H06高级算法额外最多6个结构配置，最多同时评估2个新家族。启动需有已定位误差、简单基线、数据和资源证据；费用/运行时间由pilot测量后写入限额。
- 为一次性冠军冻结预留独立预算；没有晋级候选也要完成负结果报告。

首轮12槽建议分配：R20参考、旧S20、v3完整、成熟频率、逻辑回归、浅树、ATR+流动性、旧锚+浅风险、旧锚+GBDT风险、联合四类、条件三头、成本敏感联合。无训练的常数/排序对照只消耗策略试验记录，不真的调用fit；72是上限。旧v3精简等历史版本先复现已有结果，若需要新数据重训另占槽，不偷偷扩充。

建议节奏：第1～2周完成数据/工程地基及基线；第3～4周完成第一轮联合风险与选择方法；第5～6周完成条件增量、压力与冠军收敛。仅为人力/计算安排估计，数据缺口可延长；前瞻验证另需市场时间，不写成“六周即可实盘”。

停止/转向条件：

1. 数据修正前后标签大量变化且无法解释：停止模型搜索，回到数据。
2. 学习风险不胜ATR/成熟频率基线：优先数据/特征和目标诊断，不上大网络。
3. 低风险策略只剩不涨或几乎零覆盖：报告收益风险取舍，不算目标达成。
4. 任何优势在成本、停牌、成交或同股去重后消失：不晋级交易策略。
5. 候选选择依赖已看封存结果：该窗口降为开发，登记污染，重新安排未知窗口。
6. 前瞻样本不足或罕见事件界限不可用：保持`insufficient_evidence`，不降低门槛偷过关。
