## 一句话
原方案是一套六层、四个数据库服务的递归自我改进系统。落到这个项目上，用得着的是其中三样：证据分等级、改动要过准入、失败要记下来。v0 只做这三样，记录放在项目内的 SQLite 里，并生成一套 LLM wiki 风格的 Markdown 页面供人和代理阅读，另外补了原方案没有的一条——留出数据用一次就少一次。

## 为什么引入 (第一性原理)
这个项目里由代理推进的研究，出问题的地方不在循环跑得慢，在证据被高估：

- 在看过的数据上发现的规则，被当成已经验证。
- 同一段留出数据被不同问题反复用，没有人记用了几次、比了多少条规则。
- 被否决过的想法换个说法又做一遍。
- 模型评审（JEV）给的「对齐」被读成「正确」。

原方案里对应这些问题的是验证层级、准入控制和负面记忆。其余部分（策略记忆、外部检索、Benchmark 动态难度、经验图谱）针对的是能自动判分的任务，这里没有。

## 核心思想 (讲直觉, 不堆公式)

### 1. 证据等级是算出来的
原方案按任务类型查表决定用哪一级验证器。这里改成按证据来源算：规则在哪段数据上选定、在哪段数据上计分、这类问题在那段数据上用过几次。

| 等级 | 含义 |
|---|---|
| formal | 机器检查：测试、逐行复现 |
| prospective | 规则先登记成影子，再在登记时没读过的数据上计分 |
| holdout_once | 在别的数据上选定，在留出数据上第一次为这类问题计分 |
| reused_holdout | 留出数据已为同类问题用过 |
| in_sample | 规则就是在这段数据上看出来的 |
| judge | 模型或人的判断，没有结果数据支撑 |

调用方只报「在哪选、在哪验」，等级由工具给。同一类问题在同一窗口上比过的规则数会累计，并换算成需要的 |t|。本项目回填之后，确认期上名单内筛选这一类已经比过 14 条规则，门槛是 2.91；当天事后看到的「名次加 ATR 留 10 只」t 值 2.0 和 2.33，过不了。

### 2. 数据窗口有状态
`open`（没用过）、`consumed`（用过）、`reserved`（保留）。保留窗口只能用来给事先登记、且已到成熟天数的影子规则计分；其他读取 `check` 会报违规，`trial log` 会拒收。本项目登记了三个窗口：开发期和确认期已用，2026-08-06 起保留。

### 3. 准入：代理只能提议
受保护的文件列在 `constitution.json` 里（四个冻结合约、`output/production/` 下的模型权重、宪法文件本身），每个都要求 prospective 级证据加人批准。`propose` 证据不够直接拒绝，够了也只到「待人批」；`decide` 必须带人名，代理署名会被拒绝。

### 4. 校准用实测
原方案让模型自己报置信度和能力估计。这里从账本里统计：在弱等级上显著的结果，到更强等级还成立的比例。本项目目前是 2 条里 0 条（ATR 规则的两个池子）。样本很小，但这是量出来的数。

### 5. 账本
用户定的存储是 SQLite 加 LLM wiki 风格的 Markdown，都放在使用 metaRSI 的项目目录里；mylib 只留代码和默认配置。

- `.metarsi/metarsi.db`：`events` 表只追加，每条带上一条的哈希，是唯一的记录。`windows / trials / negatives / shadows / admissions / episodes` 六张查询表在每次写入后由 `events` 重建，可以直接写 SQL。
- `.metarsi/wiki/`：`README.md`（入口和当前状态）、`graph.md`（窗口 → 问题类别 → 试验 → 否决项的图）、`nodes.md`、`trials.md`、`negatives.md`、`log.md`、`playbooks.md`。每次写入后由数据库重写，不手改。它和本目录的思想 wiki 分开：这里是账本的可读视图，那里是叙述。

直接改 `events` 能用 `verify-ledger` 查出来，但拦不住；改查询表或页面没有用，下次写入会重建。

### 6. 学习还是进化，由账本和日历决定
用户希望 metaRSI 跟着项目运行，自己判断该启动进化还是只在后台学习。`tick` 命令做这件事，规则是：进化要同时有一个理由和一条验证途径，缺一样就是后台学习。

| | 来源 | 怎么量 |
|---|---|---|
| 理由 | 影子规则到期 | 项目日历里，保留窗口内「之后已满持有期」的信号日数 ≥ 登记时写的最少成熟天数 |
| 理由 | 用户提出改进要求 | 未处理的 `request` 信号 |
| 理由 | 运行故障或指标漂移 | 近 30 天未处理的 `failure` / `drift` 信号 ≥ 2 条 |
| 验证途径 | 未用过的留出窗口 | 窗口状态为 `open` |
| 验证途径 | 保留窗口加影子登记 | 未结影子规则数没到上限（5 条） |

结果有四种：后台学习；进化的验证阶段（给到期的影子计分）；进化的留出验证（有信号、有未用窗口）；进化但只能登记影子（有信号、没有未用窗口）。另外给出已疲劳的问题类别（最近 3 条试验都没有通过）和需要用户决定的事项。

判断不用模型自报的置信度。这对应原方案里「自改进强度跟随验证层级」那条：没有比已用数据更强的验证手段时，不启动改进，只积累记录。

本项目现在的结果是后台学习：保留窗口成熟 19 个信号日，4 条影子规则最近的一条还差 41 个；没有未处理的信号；没有未用过的留出窗口；名单内筛选的 S、R 两类已疲劳。等成熟日到 60，它会转成进化的验证阶段——前提是用户先指定主规则，否则会停在「有影子到期但主规则未定」。

模式约束的是代理自己发起的改进，不约束用户明确要求的分析。

### 7. 模型审计（2026-10-05 加）
证据等级管的是一条规则在哪段数据上验过。用了两天之后发现它管不到另一类问题：滚动验证各折的模型和最后上线的模型不是同一个东西。按证据等级看，开发期的证据是合格的，实际上描述的是另外几个模型。

所以加了 `model` 命令。项目脚本把事实量出来登记（每个区块的分数是谁打的、各次训练的树数、拟合窗口多长、区块和训练数据的关系与成绩、市场状态特征的增益占比、名单和全市场的差别），工具按八条固定规则判断，上线模型有问题时 `tick` 会提示，`propose --model` 会把审计结果带进提议。规则和四个模型的审计结果见 [[2026-10-05_s20-unified-v2-and-model-audit]]。

它查的是结构和证据对不对得上，不保证模型赚钱，也不替人选模型。

## 我们怎么吸纳 / 改造
对原方案的改动和理由，全文在 `mylib/skills/meta-rsi/references/DESIGN.md`，要点：

1. PostgreSQL + pgvector + Neo4j + Redis + MinIO 换成项目内的一个 SQLite 文件加生成的 Markdown 页面。单人单机、每天几十条记录，用不上服务。第一版用的是 JSONL，同一天按用户的意见改成现在这样。
2. 验证层级从按任务类型查表改成按证据来源计算。
3. 新增「评估数据是消耗品」：窗口状态和累计比较数。
4. 最弱一级证据不能准入。原方案是限制「单轮最大改进幅度 0.1」，没有说明是什么的幅度。
5. 自报的置信度换成账本统计。
6. 第四阶段验收从「无人干预完成 3 轮改进」改成「可以自动循环，但落到受保护面的每次改动都有人批的准入记录」。原写法和 L0 的人工审批冲突。
7. 改评分口径按改优化目标处理，要人批。
8. 不逐条记思考轨迹，记到问答一级，和 wiki 的会话记录对应。

接入本项目做了这些：

- `.metarsi/constitution.json`：受保护面和四条项目不变量（不自动改合约和名单；JEV 只算 judge 级；08-06 起为保留窗口且要满 60 个成熟信号日；每笔收益要写明名单口径还是账户口径）。这份是代理起草的，之后只由用户改。
- 回填当天这条线：3 个窗口、14 条试验、7 条否决、4 条影子规则、7 条问答。更早的预登记（震荡日不建仓、阀门动作等）没有回填。
- `CLAUDE.md` 和 `AGENTS.md` 加了一节，规定四个调用时点：实验前查账和检查、出结论后登记、提出影子规则时登记、改受保护文件前提议。

## 移植提示 (必填)

### 4. 装 Claude Code 钩子
用户说：装一下 claude code 钩子。

要定的是三件事。第一，挂在哪个事件上：`SessionStart` 和 `UserPromptSubmit`，前者让新会话一开始就知道模式，后者保证每个回合都重新判断一次（影子到期、信号新增都发生在回合之间）。第二，注入多少内容：每个回合都塞十行会白占上下文，所以会话开始给完整说明，之后只给一两行；模式变了才再给完整说明，并提示代理告诉用户。第三，出错怎么办：钩子挂在用户发消息的路径上，不能因为账本有问题就把用户的消息拦住，所以任何异常都只变成一条警告，返回码始终是 0。

做的事：`metarsi.py` 加了 `hook` 子命令（读钩子的标准输入、输出带 `additionalContext` 的 JSON，输出只含 ASCII 转义，不受控制台代码页影响）；在本项目新建 `.claude/settings.json`，两个事件各挂一条命令；用合成的输入试过四种情况（会话开始、用户发消息、没用 metaRSI 的目录、输入损坏），在 bash 和 PowerShell 下都能跑，一次约 0.15 秒。`CLAUDE.md` 改成「看到 `[metaRSI]` 行就按它执行，没看到再手动 `tick`」；`AGENTS.md` 不变，Codex 仍靠约定。

没有验证的一步：钩子在真实会话里是否触发。这两个事件只在回合之外发生，本回合内测不了；而且 `.claude/` 目录是这次新建的，当前会话不会监视它，要用户打开一次 `/hooks` 或重启会话才生效。

范围：钩子装在项目级，只对本项目生效。用户级设置里原有的钩子没有动。本项目的 `.gitignore` 忽略了 `.claude/`，所以这个文件不会进 git。钩子只把模式告诉代理，不拦截工具调用。
